# V7.1 当前算法与 Complete MIP：48 箱组及以下实验

## 实验设置

- 代码提交：`c634d1e`
- 算例：24、36、48 箱组，每个规模 2 个固定种子
- V7 生产总预算：120 秒/例
- witness / Stage 1 / restricted root 软上限：10 / 10 / 60 秒
- RIM：使用生产总预算中的剩余时间
- Complete MIP：独立 120 秒/例
- 线程 / solver seed：1 / 0
- V7 与 Complete MIP 使用相同输入、业务模型、目标和峰值约束
- 未运行可选 full-domain pricing audit

V7 的整数解通过独立 evaluator 验证，因此可作为完整业务模型的全域可行
UB。V7 的 LP 和 MIP gap 只针对 Stage 1 冻结后的 restricted domain，不能
作为完整模型的全域 lower bound 或 global gap；Complete MIP gap 则是完整
模型 gap。

## 根节点与首解效率

Root closure 随规模平稳增长：

- 24 组：5.51--7.68 秒；
- 36 组：13.75--16.35 秒；
- 48 组：21.90--26.50 秒。

48 组种子 601 与旧版相同数据相比，root 从约 39.22 秒降至 21.90 秒，
轮数仍为 44，说明持久化 pricing 等优化显著减少了单轮开销。但节省出的
RIM 时间没有转化成更好的最终 UB：本轮 V7 比 Complete MIP 差 2.00%。

V7 从生产流程开始到 RIM 首个 incumbent 的平均时间约为 19.65 / 29.63 /
41.90 秒（24 / 36 / 48 组）；Complete MIP 从其阶段开始、包含建模时间的
对应均值约为 2.35 / 3.83 / 33.65 秒。48 组 MIP 均值受到种子 601 首解约
61.8 秒的影响；另一个 48 组种子约 5.5 秒即有首解。

## 结论

1. 当前算法在 48 箱组及以下已经是可完整运行的流程，根节点闭合不再是
   这一范围内的失败点。
2. pricing/root 工程优化有效，尤其显著降低了 48 组根节点时间。
3. UB 优势不稳定：36 组表现最好，但 24 组未稳定获胜，48 组两个种子均
   落后 Complete MIP。
4. V7 restricted gap 数值小于 MIP global gap，但两者证明域不同，不能据此
   宣称 V7 的全域 gap 更好。
5. 以这 6 个结果看，当前算法尚不足以支持“UB 明显且稳定优于 Complete
   MIP”的论文结论；更准确的表述是根节点效率已有明显改善，而 primal
   search/RIM 解质量仍是主要瓶颈。
